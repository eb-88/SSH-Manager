# SSH-Manager

[Deutsch lesen](./README.de.md)

SSH-Manager saves your SSH destinations in a terminal menu that runs in PowerShell or in Bash on Linux. Enter a target number to open an SSH session with the saved host, user and port. The menu is in German. The steps below use the labels you’ll see on screen.

## First launch

### PowerShell

You need Windows PowerShell 5.1 or PowerShell 7 and the OpenSSH commands `ssh` and `ssh-keygen`. To check that PowerShell can find both, run `Get-Command ssh, ssh-keygen`.

In Azure DevOps, open **Repos → Files → Clone** and copy the clone URL. Replace the placeholder below with that URL and run these commands in PowerShell.

```powershell
git clone "<clone URL>" SSH-Manager
Set-Location SSH-Manager
.\SSH-Manager.ps1
```

If the global command is available, the menu opens directly. Otherwise, the script offers to register it for your account. Enter **j** (yes) to launch the tool as `SSH-Manager` from any folder, including in a new PowerShell session. Keep the script at its current location because the command points to that file. Press **Enter** to skip registration and continue to the menu.

### Linux

The Linux version requires Bash 4.4 or later, `jq` 1.6 or later, the OpenSSH client, and `flock` from util-linux. On Debian and Ubuntu, install the commands with `sudo apt install jq openssh-client util-linux`.

Start the menu from the cloned repository.

```bash
bash ./ssh-manager.sh
```

If `~/.local/bin` is on your `PATH`, you can install the script as the `ssh-manager` command.

```bash
install -Dm755 ssh-manager.sh ~/.local/bin/ssh-manager
ssh-manager
```

## Connect to your first target

1. Enter **O** to open `Optionen`, then **N** for `Neu`. Give the target a short name such as `build-box`, then enter its hostname or IP address and your SSH username. Press **Enter** to accept port **22**, or type a different port.
2. At `Anmeldung`, choose **1** to set up a key using your server password, or **2** to use your existing OpenSSH configuration, including any required second factor.
3. Enter the target’s number in the overview. On first contact, verify the host fingerprint with your server administrator before accepting it. When you finish the remote session, type `exit` to return to the menu.

With **option 1**, the manager checks your password login before generating a local Ed25519 key pair. OpenSSH prompts for a passphrase to protect the private key. Enter your **server password a second time** so the manager can add the public key to `~/.ssh/authorized_keys` on the server. The manager verifies that the server accepts this specific key before marking setup complete. If verification fails, reconnect to retry with the same key. If the key still cannot be verified, the manager asks before authorizing it again because a new entry can bypass existing restrictions. This setup requires a Linux or Unix account with a compatible shell and write access to that file.

## Manage saved targets

The overview shows each target’s name, address, and sign-in method. In a narrow terminal, the details are stacked. Enter a target number to connect directly or **Q** to quit.

Enter **O** to open `Optionen`. Press **Enter** there to return to the overview. When adding or editing a target, press **Enter** to accept the value in brackets or **!** to cancel. You can correct invalid entries in the field where they occur.

| Input | Menu label | Action |
| --- | --- | --- |
| **N** | Neu | Add a target. |
| **S** | Suchen | Filter by name, host, username, or port. Leave the search term blank to show all targets again. |
| **B** | Bearbeiten | Select a target to edit. Renaming a target preserves its key. If only the port changes, press Enter to keep the key and verify it on the new port at the next connection, or choose **n** to set up a different one. |
| **L** | Löschen | Select a target and confirm with **j** to remove it from the list. |
| **I** | Import | Load targets from an exported JSON file. Targets with existing names are skipped. |
| **E** | Export | Save all targets to a new JSON file, even when a search filter is active. |

PowerShell and Bash use the same JSON export format. The file contains target names, hosts, usernames, ports, and sign-in methods. Public and private keys, passwords, local key associations, and OpenSSH configuration stay on the original device. On the first connection to an imported target, the manager sets up a new managed key if needed. Targets set to **OpenSSH** use the configuration on the current machine.

Target profiles are stored as `ziel-*.json` files under `~/.ssh/ssh-manager/` in your home directory. The same folder holds the keys generated by the manager. Server passwords are never saved. Removing a target leaves its local key files and the corresponding authorization on the server in place.
